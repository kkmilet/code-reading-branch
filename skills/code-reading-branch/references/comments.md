# 注释规范

三档注释，两条硬规则：

1. **注释独占整行，绝不修改任何代码行。**
2. **每个跳转点标双向指针**：`→` 往下游，`←` 往上游。

## 为什么"整行独占"

如果注释追在代码行尾（`x = 1  # 说明`），剥离时要精确切到字符位置，还要处理字符串里的 `#`。一旦手滑改了代码行里的一个空格，"有没有动过业务代码"就说不清了。

整行独占之后，剥离规则只有一条：删掉所有以 `[READ]` 开头的行。剩下的字节必须和原文件一模一样——这件事可以被脚本证明。

## 为什么"双向指针"

IDE 的 `Go to Definition` 只能往下跳：从调用跳到定义。**看不到谁在调它**。

注释补上这个缺口：

- `→` 声明"我下面会调谁"，用户跳过去之后知道自己在链条的哪一段。
- `←` 声明"我从哪来"，用户在深文件里打开时，一眼能看到入口。

没有 `←` 的文件，用户跳进来就丢了上下文——这正好对应最常见的"跳转故障"。

## 格式

### Python

文件头（L1）：

```python
# [READ] ── 第2站 · 接口层 ──────────────────────────────
# [READ] 干什么：接收下单请求，校验参数后交给 OrderService，自己不写业务规则
# [READ] ← 上游：config/urls.py:23 挂到 POST /api/orders/
# [READ] → 下游：OrderService.create()（services/order.py:58）
# [READ] 改这里注意：事务边界在 Service 里，别在这加 @transaction.atomic，会嵌套出错
# [READ] ──────────────────────────────────────────────────
```

函数头（L2）：

```python
    # [READ] ← 被 views.py:41 post() 调用
    # [READ] 建订单并扣库存。入参是已校验的 dict；副作用：写 orders 表 + 发 order.created
    # [READ] → 调 inventory.reserve()（clients/inventory.py:12）、Order.save()（本文件:88）
    def create(self, data):
```

行内（L3）：

```python
        # [READ] 先扣库存再写库：写库失败时库存不会自动回滚，这是已知坑
        inventory.reserve(sku, qty)
```

### Go / JavaScript / TypeScript

把 `#` 换成 `//`，其余不变，缩进跟随被注释的代码。

```go
// [READ] ── 第2站 · 接口层 ──────────────────────────────
// [READ] 干什么：注册路由与中间件，不写业务逻辑
// [READ] ← 上游：cmd/api/main.go:18 调用 NewRouter(deps)
// [READ] → 下游：handler/*.go 各业务 handler；middleware/auth.go
// [READ] 改这里注意：新增接口在这里注册；鉴权限定在路由组上，别全局挂
// [READ] ──────────────────────────────────────────────────
```

## 三档各写什么

| 档 | 适用范围 | 写什么 | 上限 |
|---|---|---|---|
| L1 文件头 | **仅站内文件**，每文件 1 个 | 位置、干什么、← 上游、→ 下游、改这里注意 | **6 行**（含首尾分隔线） |
| L2 函数头 | 站内文件的公开函数 | 一行说明 + 入参出参 + 副作用 + 双向指针 | 每文件 ≤6 个，每个 ≤2 行 |
| L3 行内 | 仅主链路关键段 | 这一步在干什么 / 为什么这么写 | 每文件 ≤10 处，每处 1 行 |

**6 行装不下，说明你想说的不是"这是什么"，而是"我读懂了什么"**——后者属于对话，不属于注释。

同一事实只写一处：注释里写过"上游是谁"，`READING.md` 和对话里就不再重复。

**站外文件一个注释都不加。** 它们的存在感只在 `READING.md` 的模块地图那一行。

给站外文件写注释的代价：分支改动文件数翻倍，而用户并不会读——纯噪音。省下的注意力，全部留给主干。

**密度上限（防淹没）**：单个文件的注释行数 ≤ 文件总行数的 15%，且 ≤40 行。

超过就说明在逐行翻译，不是在标注。注释一旦盖过代码，用户会开始跳着看，那还不如不写。

## "改这里注意"只写三类

1. **不写就会改错**：如"新增字段要先改 `schemas.py`，否则序列化会丢掉"
2. **看不出来但影响行为**：隐式事务、中间件顺序、全局异常处理、缓存键前缀、软删除、信号触发
3. **名字骗人**：`XxxBankAccountPO` 实际映射 `company_account` 表

不写：显而易见的循环、普通 getter/setter、框架标准写法。

## 渐进式术语引入（A → B）

同一个概念只在**第一次出现**时展开（A 式，2~3 行），之后一律一句（B 式）。

```python
# 第一次遇到 serializers —— 展开
# [READ] serializer 是"翻译官"：把 HTTP 传来的 JSON 变成 Python 对象，
# [READ] 顺便检查类型和必填。is_valid() 返回 False 就直接抛 400，不会往下走。
serializer = OrderCreateSerializer(data=request.data)

# 第二次遇到 —— 一句带过
# [READ] 同样的翻译官，校验规则在 schemas.py:31
serializer = RefundSerializer(data=request.data)
```

判定标准：这个概念外行是否第一次见。是 → 展开一次；否 → 直接写 B。
展开过的概念记进术语表，避免第二次又讲一遍。

## 引用怎么写（实战改出来的规则）

**写「完整相对路径 + 符号名」，不写行号。**

```python
# [READ] → 下游：Model.generate()（src/smolagents/models.py）
# [READ] ← 上游：_run_stream()（src/smolagents/agents.py）
```

两个理由，都是实测踩出来的：

1. **行号会自我失效。** 在文件里插入 20 行注释后，同一个文件里的 `_run_stream` 从第 540 行移到了第 552 行。任何写死行号的引用，会在你写完注释的那一刻变错。文档（`READING.md`、旅程图）同理——它指向的是**被注释过之后**的文件。
2. **短文件名会歧义。** 真实仓库里常有 `tests/fixtures/agents.py` 这种同名文件；写 `agents.py`，读者可能跳到测试夹具里去。

路径必须能唯一定位。同名文件多的项目尤其要写全。

## 插入操作规范（防手滑）

1. **按行插入**，不要用字符串替换拼接。字符串替换会把注释粘到上一行代码的末尾，直接违反"不改代码行"——实测中这真的发生了，`@dataclass` 和注释被粘成一行。
2. 插完立刻自检：**每个含 `[READ]` 的行，都必须以 `#`（或 `//`）开头**。有例外就是出事了，回滚重做。
3. **保留原文件换行符。** 原文件是 LF 就写 LF。写成 CRLF 会让整个文件在 diff 里显示为"全改"，注释就白写了。

   Windows 上 Python 的默认写法会踩这个坑，**必须显式指定**：

   ```python
   p.write_text(text, encoding="utf-8", newline="\n")   # 对
   p.write_text(text, encoding="utf-8")                 # 错：Windows 会写成 CRLF
   ```

   改完跑一次 `verify.py`，出现「换行符被改动」就是在这一步踩了。
4. 插完对改动文件跑一次语法检查（`python -m py_compile <文件>`，只编译不执行），确认没有破坏语法。

## 路径核实（落笔前必做）

注释里每写一个 `文件:函数` 引用，落笔前 grep 确认它真的存在：

```bash
grep -rn "class OrderService" --include=*.py .
grep -rn "def create" services/order.py
```

grep 不到 → 只写函数名，不写路径；并把这条记进 `READING.md` 的【存疑】。

**理由**：注释里一个跳不过去的引用，比没有注释更糟——用户会开始怀疑整份注释。

## 禁止

- 不改代码行、不调格式、不重排 import、不补类型标注
- 不写"这里可以优化""建议重构"——这是阅读助手，不是评审
- 不写没有证据的话
- 不把整段业务逻辑翻译成中文散文——注释要短，长解释放对话里
- 不在注释里写 TODO 或待办

## 剥离规则（脚本执行，这里只作说明）

```
Python:      ^\s*#\s*\[READ\]
Go/JS/TS:    ^\s*//\s*\[READ\]
```

匹配到的**整行删除**，其余字节不动。删完必须与基线逐字节一致。
