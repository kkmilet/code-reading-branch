# 注释规范

两条硬规则：

1. **独占整行，不改任何代码行。**
2. **每行不超过 72 个显示宽度**（中文算 2，英文算 1）。

## 为什么是 72

IDE 一屏大约 80~100 列，扣掉行号、侧边栏、折叠箭头，72 是安全线。

超过 72，编辑器要么横向滚动，要么自动折行——**一条逻辑注释变成三行显示**，文件头立刻占满一屏。读者觉得"注释怎么这么长"，多半是这个原因，不是行数多。

判断方法：把注释贴进 IDE，出现横向滚动条或看到软折行，就是超了。

## 不用符号

禁用：

| 符号 | 换成 |
|---|---|
| `──`、`━━`（框线） | 什么都不用，直接写标题 |
| `←`、`→`（箭头） | 「谁调它」「它调谁」 |
| `·`（间隔点） | 顿号或空格 |
| `①②③` | `1.` `2.` `3.`，或者直接分行 |
| `【】` | 普通冒号，或不用 |

理由：这些符号不承载信息，在等宽字体里还会错位。读的人要先猜"这个箭头是向上还是向下"。

标签一律用中文词：**谁调它 / 它调谁 / 改之前先看**。

## 三档

### L1 文件头（只给站内文件）

**≤12 行，每行 ≤72 宽**。四件事，缺一不可：

```python
# [READ] 第 5 站：Agent 执行循环
# [READ] 这是主循环。每轮让模型想一步、执行、看结果，
# [READ] 直到它给出最终答案，或者步数用完。
# [READ] 谁调它：run()，命令行和界面都从这里进。
# [READ] 它调谁：Model.generate() 拿模型输出，再交执行器跑。
# [READ] 改之前先看：要加新的 Agent 类型，只实现 _step_stream，
# [READ] 不要动 run。
```

每行都在 40 字以内，读的时候不用转头。

### L2 函数头（站内文件的公开函数）

**≤2 行**。写"做什么 + 副作用"，不写"是什么"：

```python
    # [READ] 建订单并扣库存。入参是校验过的字典。
    # [READ] 会写 orders 表，并发一条 order.created。
    def create(self, data):
```

副作用专指：写库、发消息、调外部、改全局状态。没有就不写第二行。

### L3 行内（主链路，或这行有坑）

**1 行，最多 2 行**：

```python
        # [READ] 先扣库存再写库。写库失败时库存不会退回来。
        inventory.reserve(sku, qty)
```

## 密度下限（防"只有表头"）

只给表头，等于给了封面没有正文。每个站内文件至少：

- **1 条 L1**
- **2 条 L2 或 L3**（文件短于 50 行时至少 1 条）

这是下限，不是建议。写完自己数一遍。

## 非基础语法要解释

遇到下面这些，**就地加一行**，说明它在这里做什么。不是解释语法，是解释它为什么出现在这。

装饰器、`yield`、`with`、推导式、`*args` / `**kwargs`、闭包、`lambda`、三元表达式、`try/except/else/finally`、`async/await`、`property`、`classmethod` / `staticmethod`、`super()`、元类、描述符、`dataclass`、类型标注、海象运算符、切片、枚举。

写法对比：

```python
# 错：讲语法本身
# [READ] 装饰器是接收函数并返回函数的高阶函数。

# 对：讲它在这里干什么
# [READ] @property 让 total 能像属性一样读：外面写 order.total，
# [READ] 不用写 order.total()。
@property
def total(self):
    ...

# 对：讲 why
# [READ] with 管连接的关闭：这段抛异常也会关掉，不用手写 finally。
with get_conn() as conn:
    ...

# 对：讲这个写法省了什么
# [READ] 这里用生成器分批取，避免一次把十万行读进内存。
for row in iter_rows(conn):
    ...
```

判断标准：**读者看完这一行，能说出"为什么这里要这么写"，而不是"这个语法叫什么"。**

## 一行最多两个函数名

```python
# 错：罗列
# [READ] 它调谁：A()、B()、C()、D()、E()

# 对：只留关键的
# [READ] 它调谁：Model.generate() 拿模型输出，再交执行器跑。
#        另外还有三个辅助函数，不在这条主线上。
```

对话里同理：一段讲解里出现的函数名不超过 3 个，其余用"另外几个辅助函数"带过。

## 渐进式术语引入

同一个概念只在**第一次出现**时展开（2 行以内），之后一句带过。

```python
# 第一次遇到 serializer
# [READ] serializer 是翻译官：把 HTTP 传来的 JSON 变成 Python 对象，
# [READ] 顺便检查类型和必填。
serializer = OrderCreateSerializer(data=request.data)

# 第二次
# [READ] 同样的翻译官，规则在 schemas.py。
serializer = RefundSerializer(data=request.data)
```

展开过的记进术语表，不要第二次又讲。

## 引用怎么写

**写「符号名 + 完整相对路径」，不写行号。**

```python
# [READ] 它调谁：Model.generate()，在 src/smolagents/models.py。
```

两个理由：

1. **行号会自我失效。** 插入 20 行注释后，同文件里的 `_run_stream` 从 540 行移到 552 行。写死的行号在你写完的那一刻就错了。
2. **短文件名会歧义。** 仓库里常有 `tests/fixtures/agents.py`，写 `agents.py` 读者会跳到测试夹具。

路径必须能唯一定位。

## 插入操作规范

1. **按行插入**，不要用字符串替换拼接。替换会把注释粘到上一行代码末尾，直接违反第一条硬规则。
2. 插完自检：**每个含 `[READ]` 的行都必须以 `#`（或 `//`）开头**。
3. **保留原文件换行符。** Windows 上 Python 要显式指定：

   ```python
   p.write_text(text, encoding="utf-8", newline="\n")   # 对
   p.write_text(text, encoding="utf-8")                 # 错：写成 CRLF
   ```

4. 对改动文件跑一次 `python -m py_compile`，确认没破坏语法。
5. 跑 `scripts/comment_style.py`，检查宽度、符号、密度下限。

## 剥离规则

```
Python:    ^\s*#\s*\[READ\]
Go/JS/TS:  ^\s*//\s*\[READ\]
```

匹配到的整行删除，其余字节不动。删完必须与基线逐字节一致。
