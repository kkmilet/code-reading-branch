# 交付物规格

`READING.md` 除了路线和旅程，还需要三样东西才「用得上」：**能力清单**、**踩坑**、**最小片段**。
另有一个变体：**模块模式**（只看一个模块时换结构）。

## 一、能力清单（回答"这项目能做什么"）

路线告诉你"怎么走"，能力清单告诉你"有什么"。**二开时你接到的需求通常是一个名词**——"加个导出""支持批量扣减"——你要先在清单里找到最接近的现成能力，再顺着它改。

三级，**宁可少而准**：

| 层级 | 判定 | 数量 |
|---|---|---|
| **核心** | 去掉它项目不成立；README 首屏强调 | 3~8 条 |
| **常用** | 日常高频，示例里出现多 | 5~12 条 |
| **进阶** | 要懂内部机制才用得好，误用有风险 | ≤6 条 |

核心能力每条**五字段**，常用能力只给表格行：

```markdown
### C-03 自定义工具 ★★★

- **一句话**：给 Agent 加一个能被调用的小能力，不需要改框架
- **什么时候用**：要接入内部系统、或包装一段固定逻辑
- **最小片段**：见下方「最小调用片段」
- **代码位置**：`Tool`（src/smolagents/tools.py）
- **高频度依据**：`examples/` 下 25 个示例中 19 个定义了自定义工具
```

**高频度只接受三种依据**，写不出依据就不打星：

1. 本仓库 `examples/` 或 `tests/` 里的出现次数（给出 grep 命令与命中数）
2. README / 文档里占的篇幅
3. 默认开启的配置项（说明官方认为你会用）

禁止：

- 把配置项当能力（"支持 200 个配置"不是能力）
- 把实现细节当能力（"三级缓存"是机制，不是你能调用的能力）
- 全打 ★★★（失去区分度）
- 拍脑袋打星

## 二、踩坑（四段式，缺一不可）

```markdown
### 坑 1：扣库存成功但下单失败，库存不回滚

- **现象**：订单表没有记录，但库存已经少了 1；日志里只有一条 `InventoryReserved`，没有异常
- **原因**：① 扣库存是 HTTP 调外部服务，② 写库在本地事务里。两件事没有共同事务，②失败不会触发①的补偿
- **解决**：在 `create()` 的异常分支里补一次 `inventory.release()`；或改成先写库再扣库存（把失败点前移）
- **如何避免**：新增"跨服务写操作"时，先问一句"第二步失败了，第一步谁来撤"
```

规则：

- **现象必须是能搜到的确切报错文本或行为**。推不出来就写「常见报错（未在本项目验证）」，**禁止凭记忆编造报错**。
- **原因写到机理**，不是"配置错了"。
- **如何避免必须是可执行动作**，不是"注意 XX"。
- 3~8 条，宁少勿多。20 条浅坑不如 5 条深坑。

优先级：环境/版本 > 配置 > API 误用 > 性能。

## 三、最小调用片段

目的：让用户**看一眼就知道怎么用**，建立体感。

- 从 `README` 的 Quick Start 或 `examples/` 里**照抄**，不要自己编
- 5~15 行，保留原始 import
- 标注来源：`照抄自 README 的 Quick Start，未验证`
- 依赖凭证/外部服务时注明："需要 X 才能真跑"

**不执行**。不要替用户跑，也不要承诺"这段能跑"。

## 四、模块模式（只看一个模块时）

用户说"我只想搞懂 orders 这个模块"时，**不要套整仓模板**。换成六节：

1. **一句话定位**：这个模块在系统里干什么
2. **边界**：对外暴露什么（公开函数 / 路由 / 事件 / 表）、依赖谁
3. **内部结构**：3~5 个核心符号，一句话一个
4. **一次调用**：模块内的主链路（函数级即可，不必追到数据库）
5. **改这里注意**：2~3 条
6. **和谁有关**：上游调用方、下游被调方

不写：全景画像、6~8 站路线、能力清单。**模块没有"能力清单"，只有"职责"。**

判断用哪种模式：用户给的是仓库根 → 整仓模式；给的是某个目录，或明说"只看 X" → 模块模式。

## 五、假设表（静态推断的前提）

静态分析必然有前提，写出来，让用户一句话就能推翻：

```markdown
| 我的判断 | 依据 | 如果错了会怎样 |
|---|---|---|
| `src/` 是主代码，`examples/` 只是用法示例 | 目录结构 + 两个目录的 import 方向 | 若 examples 里藏了核心实现，第 5 站会漏东西 |
| HTTP 是最主要入口，CLI 只是辅助 | `cli.py` 只有 294 行且只做参数映射 | 若你们实际只用 CLI，路线要倒过来 |
```

假设要**可被一句话推翻**。不要写"假设这是个正常项目"这种没法反驳的话。

## 六、过期与重跑

`READING.md` 会过期。头部必须有 `base_commit`，末尾写一段：

```markdown
## 这份导航什么时候会过期
- 需要重跑：新增/删除了顶层模块、依赖大版本变更、主链路改了入口
- 不用重跑：业务逻辑改动、加字段、修 bug
- 重跑方式：在同一仓库新开 `reading/<新日期>` 分支，覆盖 `READING.md`
```

## 优质判据

- [ ] 核心能力 3~8 条，每条五字段齐全
- [ ] 每个 ★ 都有可核查的依据
- [ ] 踩坑 3~8 条，四段齐全，现象可搜索
- [ ] 报错文本有出处，没有编造
- [ ] 最小片段照抄自官方示例，标注了来源
- [ ] 模块模式没有套用整仓模板
- [ ] 假设表每条都能被一句话推翻
- [ ] 写了"什么时候会过期"
