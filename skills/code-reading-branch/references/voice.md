# 说话方式

讲解的质量一半在内容，一半在句子。这份文件定句子。

## 三条底线

1. **清楚**：一句话只装一个事实。读者读完不用回头再看一遍。
2. **有信息量**：每句话都应该让读者多知道一件事。不增加信息的句子删掉。
3. **有判断**：说"这里是坑"比说"这里需要注意"有用。敢下结论，不确定就说不确定。

## 五种坏味道（按出现频率排）

### 一、AI 味

特征：开场铺垫、结尾总结、三段式排比、万能形容词、过度对冲。

| 别写 | 为什么 |
|---|---|
| 首先…其次…最后… | 结构词不承载信息，删掉后句子照样成立 |
| 总的来说 / 综上所述 | 总结已经说过的内容，等于重复一遍 |
| 值得注意的是 | 真正值得注意的事，不需要先声明"值得注意" |
| 让我们来看看 | 没有"我们"，直接看 |
| 强大的 / 灵活的 / 优雅的 | 形容词不提供信息，换成它到底能做什么 |
| 希望对你有所帮助 | 客套，占地方 |
| 可能 / 通常 / 在一定程度上 | 对冲词。不确定就说"我不确定"，别用副词糊过去 |

### 二、幼稚

特征：过度比喻、感叹号、把读者当学生。

| 别写 | 改写成 |
|---|---|
| 想象一下，view 就像餐厅服务员，把点单传给后厨哦～ | view 不做业务，只把请求转给 service |
| 简单来说 | 直接说简单版本，不要先说"简单来说" |
| 你需要记住 | 这块的关键是 |
| 是不是很简单呢？ | 删掉 |

比喻只在**概念本身没有日常对应物**时用一次，用完就回到术语。一段里出现两个比喻，说明在回避讲清楚。

### 三、黑话

特征：抽象名词堆叠、自造缩写、把动词名词化。

| 别写 | 改写成 |
|---|---|
| 通过能力矩阵实现业务闭环 | 它收请求、调库存、写订单 |
| 在链路上承担编排职责 | 它在中间，按顺序调三件事 |
| 对参数进行校验 | 校验参数 |
| 进行数据持久化 | 写库 |
| 底层逻辑 / 抓手 / 赋能 / 落地 | 具体动作 |

**术语保留英文原名**：写 `serializer`，不写"序列化器"；写 `middleware`，不写"中间件层"。因为读者查文档、搜报错、问同事用的都是原词。

但术语第一次出现要有一句人话，之后直接用原词。

### 四、啰嗦

特征：先铺垫再结论、每个动作解释目的、同一件事说两遍。

| 别写 | 改写成 |
|---|---|
| 这里我们之所以要使用事务，是因为我们需要保证一致性，也就是说如果中间某一步失败，那么前面的操作也需要回滚，从而避免出现部分成功的情况 | 事务边界在这：扣库存和写订单要么都成，要么都撤 |

改写方法：**先写结论，再写一句原因，然后停。** 第二句之后的内容，八成是自我解释。

### 五、空洞

特征：没有具体指代的提醒。

| 别写 | 改写成 |
|---|---|
| 注意这里的配置，配错了会有问题 | `.env` 少 `SECRET_KEY`，启动报 `KeyError` |
| 这个函数比较重要 | 所有下单请求都走这里 |
| 建议关注性能 | 这里每次循环查一次库，1000 条就是 1000 次 |

判据：**把这句里的专有名词全删掉，如果句子还成立，那它就没信息。**

## 句子级规则

- **一句一个事实。** 超过 25 字的句子，拆。
- **动词开头。** "校验参数" 不是 "对参数进行校验"；"写库" 不是 "完成数据持久化"。
- **能写数字就写数字。** "转了 6 圈" 不是 "转了很多圈"；"3 个文件" 不是 "若干文件"。
- **每段第一句是结论**，不是铺垫。
- **判断用是/不是**，不用"可以说是"、"某种程度上"。
- **连用三个"的"就重写**。

## 不堆符号

注释和文档都不写框线 `──`、箭头 `←→`、间隔点 `·`、圈号 `①②③`。

这些符号不承载信息，读的人还要先猜方向。标签直接用中文词：谁调它、它调谁、改之前先看。

注释每行不超过 **72 个显示宽度**（中文算 2，英文算 1）。超了编辑器会折行，一条注释变成三条，读者要重新找句头。

## 函数名别堆

一段话里最多出现 3 个函数名，其余用"另外几个辅助函数"带过。

同一条注释里最多 2 个。写"它调 Model.generate() 拿模型输出"，比写"它调 A()、B()、C()、D()"有用。

## 长度上限

| 对象 | 上限 |
|---|---|
| 单个函数的讲解（不含代码） | 120 字 |
| 每站开场 | 1 句 |
| 每组收尾 | 1 句 |
| 坑 | 现象 1 句 + 原因 1 句 |
| 对话里的表格 | ≤5 行，超了改成分点 |
| 反问、感叹、客套 | 0 |

## 语气

- **陈述，不劝说。** 说"这样会触发两次"，不说"建议你最好……"。
- **不夸用户。** 没有"这个问题问得好"。
- **不承诺。** 没有"相信你很快就能掌握"。
- **承认不知道。** "这块我推不出来" 比编一个解释强。
- **可以用"你"。** 但不用"我们"来制造虚假的共同体。

## 交付前自检

1. 删掉第一句，信息少了吗？没少就是铺垫。
2. 有没有一句话删掉后读者也不会做错事？有就删。
3. 有没有可以换成数字的模糊词？
4. 有没有在总结刚说过的话？
5. 读出声，像不像一个同事在讲话？
